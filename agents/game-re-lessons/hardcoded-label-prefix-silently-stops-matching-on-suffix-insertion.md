# A hardcoded `startsWith()`/exact-string prefix used to classify census hits silently stops matching when a sibling label grows an inserted suffix

**When it bites:** a corpus-wide scan buckets its hits by testing a hit's
own label/name string against a literal prefix (`h.img.startsWith('slot2292
(field overlay)')`, or any similar "does this belong to group X" string
test) to separate expected/known hits from an "other"/unclassified bucket —
especially right after a sibling disc/variant/instance gets its own label by
inserting extra text into an existing naming template (`"... (field
overlay)"` → `"... (field overlay, disc2)"`) rather than appending a wholly
separate suffix after it.

## The trap

A literal prefix string baked in when only ONE label shape existed
(`'slot2292 (field overlay)'`, ending in a closing paren) silently stops
matching the moment a sibling label is generated by inserting new text
*before* that same closing paren rather than after it
(`'slot2292 (field overlay, disc2)'` — the character at the position the
old prefix's last byte expected is now `,`, not `)`). `String.startsWith`
returns `false` with no error, no warning, no exception — the hit is simply
routed to whatever "unclassified"/"other" bucket the script's fallback logic
uses, and the script keeps running and reporting a plausible-looking (but
wrong) result.

## Confirmed case

Valkyrie Profile (PSX, `valkyrie`): `verify-section3-consumers.ts` filtered
census hits with `h.img.startsWith('slot2292 (field overlay)')` — correct
for the disc1 image, named exactly `'slot2292 (field overlay)'`, but never
matching the disc2 image, named `'slot2292 (field overlay, disc2)'` (a
comma sits where the old prefix's trailing `)` expected). Every disc2 hit
for that image silently fell through into the script's `otherHits` bucket
instead of being counted against the expected per-image total — for an
unknown number of prior rounds, since the script always ran to completion
and printed a result, just a wrong one, with the disc1-only figures
happening to look self-consistent on their own.

## Fix

Prefer testing on a stable, disambiguating TOKEN (`image.discId ===
'disc2'`, a separate `slot` field) rather than a substring/prefix test
against a human-composed label string that other code is free to grow or
reformat later. If a name-string test is unavoidable, name images with the
disambiguator as a suffix appended *after* a fixed, closing delimiter
(`'slot2292 (disc1)'` / `'slot2292 (disc2)'`, not `'slot2292 (field
overlay)'` vs. `'slot2292 (field overlay, disc2)'`) so a prefix test up to
and including the first `)` stays valid regardless of what's inserted
later — and audit every existing `startsWith`/prefix-match census filter in
a project for the same shape once one instance is found, the same way a
`grep`-discoverable sweep catches other systemic script bugs (see
`tracker-prose-is-not-evidence.md`'s eleventh variant for the sweep
technique). A cheap regression check: for every hit bucket a script
prints a count for, assert the buckets partition the hit set exactly (sum
of all buckets equals total hits) — a silent misrouting shows up as a
bucket total that's suspiciously exactly halved (one disc's worth) rather
than as an outright error.
