# "I searched and found nothing" is a weak negative; "I enumerated every access root" is a strong one

**When it bites:** you're about to write "no code reads/writes this / no caller / item is inert / value N never occurs" on the strength of zero-hit searches. Also: dismissing a lead because it matches none of an inventory you built. Also (positive claim): two code regions cite the same literal RAM address on a platform where overlays share a load address, and you're about to call it one structure.

A **shape-based** negative enumerates instruction/operand patterns that *would* access the thing and finds none. It is only as complete as your list of shapes, and it fails silently: every encoding you didn't think of is a hole you can't see. A **root-based** negative enumerates every way an address can be *formed* (base registers, relocations, literal bases, index families, places where a pointer gets registered), then follows each root to a finite, classified set of accesses. That set can be counted, and a negative over it is real. When a negative closes a question, contradicts the docs or ends the search, make it root-based or write it as "a search that came up empty". Never write it as "proven absent".

**Check / fix:**
1. **Positive control first.** Run the identical search against something known live *for the same reason* (plus a negative control that should hit). If the control also returns zero, the search can't tell anything apart.
2. **Count the roots. One compiler convention ≠ one addressing mode.** In SAS/C binaries, A4-relative accesses have no reloc entry, so a reloc walk can't see them, while an A4-displacement scan can't see relocated absolutes. Run both. The tell is `(d16,A4)` operands and reloc-patched absolute longs in the same function. Pure SAS/C chain: no relocs into the table → every `(d16,A4)` displacement in range → pointer-escape analysis → classify what remains.
3. **An array is a family of constants.** The assembler folds literal indices, so also search `base ± stride×n` for every valid index `n`. The mirror case: an entry reached only by a runtime index never appears literally, so zero hits on an *entry* address is the expected result. Resolve the base first.
4. **Indirect calls** (`JSR (An)`, a shared `jmp (a1)` dispatcher) are structurally invisible to direct-call scans. Trace every write to the register (including loads from memory), or search for the target address as a 32-bit *data* value and follow the idiom that stores it to find every sibling registration.
5. **"Does value N ever occur"** is a census of every *write* to the variable (`move.w #imm,abs` / `clr.w abs`), not of the dispatch arms. Reads show what the code *could* do. Writes show what actually happens.
6. **Value absent from every literal search:** suspect a runtime table lookup inside the id's consumer (trace the body of the call that takes the id), or a VM computed-address mode (shape-match the consuming routine by control flow, then enumerate its `PUSHI K; CALL` callers). Confirm the absence before you widen the search again.
7. **An inventory used as a filter needs its own completeness check:** a chain such as `base + slots*stride == next.base`, a checksum, or a count from an unrelated source.
8. **Widen the file scope:** every overlay or module sharing the address space (paired modules, per-room modules, siblings at the same base), *and* nested compressed sub-blocks inside cataloged containers (re-scan for magic bytes past offset 0). A cheap sweep: does the subsystem build *any* `lui reg,HI` in that hi-word range?
9. **Re-run a load-bearing zero with a simpler, independent tool** (`bytes.find()`, `grep -a`). Disassembler searches miss hits.
10. **Techniques that share a primitive count as one.** Ask what each scan's actual core is (shared helper, "stop at first j/jr/jal" rule, shared bias tracker). Diversify with methods that fail differently: read the disassembly directly, or search the project's own prose.
11. **Complete census, still negative, but the thing is known to exist:** the root may be wrong. Re-root on a low-fan-out anchor, such as a registry pointer with few xrefs or a format-defining instruction pair.
12. **An unexplained anomaly in the brief may be the answer.** A hunk storing fewer bytes than declared means you were searching for file bytes that don't exist (BSS).
13. **"Name never referenced"** says little where assets load by computed names. First measure what fraction of known-live files have a literal name in the binary.
14. **Address match as identity:** find which overlay each citing function belongs to and whether the two are ever resident at the same time.

**Canonical example:** Epic (Ocean, Amiga, `hunter`). Across sessions, a filename pool was written up as "possibly dead content" after three structurally distinct zero-hit scans (LEA/PEA; every addressing mode plus branch targets; the whole `HUNK_ABSRELOC32` table). Running all five scan shapes against **nine `*_MAP` filenames that definitely load** gave the identical zero, which invalidated three sessions of negatives at once. The executable holds two separately linked images, and the pointers live in the other one's address space (`hunk − 0xCAB6`; see `two-linked-images-one-hunk-module-relative-addresses.md`). A third pool reached by PC-relative `LEA` scored 4 hits, which proved the scan worked when the reference sat in the space it searched. Separately, 94 shipped files in that game have no literal name in the executable at all.

**Variants:**
- War in Middle Earth (`middilgard`): the Elven cloak's "confirmed inert" came from an operand-shape census and was wrong (`bitfield-spans-multiple-addressable-bytes.md`). Death endings were ruled out soundly, because a raw scan found exactly four game-end dispatch sites. A grep for the array base `10674` missed consumers compiled as `-10650`/`-10642`.
- Knights of the Round (CPS1, `kolbold`): a re-init routine with zero direct callers in 1 MB of ROM. Its address as data appeared at 2 registration sites, leading to a 16-slot task kernel with 77 registrations (`engine-implements-cooperative-task-kernel.md`). Carrier Command: `$CB5C` was "ruled out" by 12 direct callers when the call in question was `JSR (A2)`.
- D&D: Tower of Doom (CPS2, `kolbold`): a byte-exact loop signature found 5 of 9 object pools. Checking the chain would have exposed the `0x25c8`..`0x43c8` gap where the dismissed target's pool lived.
- Valkyrie Profile (PSX, `valkyrie`): 7 "diverse" techniques shared one forward-scan primitive that stops before the delay slot (`mips-delay-slot-instruction-always-executes.md`). The project's own prose named the producer (`doc-self-cross-reference-before-fresh-disassembly.md`). Six passes rooted at `obj+0xc8` failed because the renderer reads a draw-list copy. `0x8007f1e4` sits in two never-co-resident overlays (TOC 1491 vs 2292) with unrelated structures. A one-overlay census became a corpus-wide negative only after scanning 73 files plus nested sub-blocks (`compressed-container-members-invisible-to-magic-scan.md`).
- Chaos Legion (PS2, `flower`): track LBAs are never immediates. `CdFileOpen(fno)` indexes a hidden 8-byte `(size, LBA)` table. Hunter (`hunter`): `r2 /x` missed a `0x157c(a5)` consumer that `bytes.find()` found. Phantasie III (`nicodemus`): a write census of the map-id global gave exactly `{0,1,2,4}`, and merged data+BSS explained the missing table bytes (`hunk-data-shorter-than-declared-is-merged-bss.md`).
