# A field the reader labels "unknown, constant, retained verbatim" can be a count the engine's parser consumes — generated output must replay the loader's own grammar, not just round-trip

**When it bites:** about to ship *generated* (not round-tripped) output of a
format whose reader was reverse-engineered from data — an importer, a
writer, a from-scratch builder — and the reader's struct has a field
documented as "unknown, always N in the corpus, preserved verbatim" that the
writer therefore has to *invent* a value for. Also: every round-trip test,
corpus-census lint rule and reference-decoder comparison is green, and the
first in-game load of generated output crashes anyway.

## What went wrong

Fire Emblem: Three Houses (Switch, `chimera`): the project's G1M reader
modelled a submesh record as a flat 56-byte struct with one field at offset
`0x20` called `unknown5` ("always 1, retained verbatim"). The glTF→G1M
importer wrote `0` there for every fresh submesh. The engine's parser
(`main+0xa3478c`) reads the record as a `0x24`-byte head plus
`[head+0x20]` × 20-byte draw ranges — the flat 56-byte model is only correct
when that field is exactly 1. With 0, the loader's *sequential* stream fell
20 bytes behind per submesh, a later handler short-read and returned false,
the parser freed the half-built model and returned NULL, and an unguarded
`ldr x8,[x20,#0x70]` faulted at VA `0x0`. Every one of six pipeline-built
PACKs crashed the game on first contact; the crash was misattributed for
most of a day to the mod that carried one of them (see
`live-ab-isolation-names-carrier-not-mechanism.md`).

Nothing in the existing verification could see it:

- **Round-trip tests preserve the constant.** Native in → native out keeps
  `unknown5 = 1`, so the reader/writer pair is byte-exact and the grammar
  divergence never appears. Only *generated* records exercise the writer's
  invented default.
- **Corpus-census lint rules check what the reader models.** The lints
  compared counts, ranges and versions the reader already parsed; a field
  the reader treated as opaque never got a rule.
- **A second instance in the same pass, same blindness:** an *empty* Socket
  section is 16 bytes (an 8-byte `{count, 0x100}` head, `mov w3,#8` at the
  handler) where the writer emitted the generic 12-byte section header
  alone — invisible because the round-trip path captured native raw
  sections verbatim and only a from-scratch build ever hit the default
  branch.

## The fix

1. **Replay the target's own disassembled parser over the generated bytes
   and require `consumed == declared` at every level.** Disassemble the
   loader, note which header size/count fields it *actually uses* (here:
   GM1G array-section `size` fields are never used to seek; an unknown
   section type is not skipped), which records have variable-length tails,
   and what makes a handler return false. Encode that as a lint rule
   (`g1m-engine-parse-walk` in `fe3h-pack-lint.ts`) and run it over the
   native corpus as the control (569/569 pass) and over every generated
   file (every pre-fix pipeline PACK fails).
2. **Treat every "constant" the writer must invent as a grammar question,
   not a default.** If a field only ever needs one value, the format usually
   wouldn't store it (same tell as
   `self-describing-length-field-mistaken-for-corpus-constant.md`, the
   read-side twin of this lesson). Before defaulting it, find the
   instruction that reads it: a count feeding an address computation
   (`add x8,x8,x8,lsl #2; lsl x28,x8,#2` = ×20) is load-bearing.
3. **Rename the field once its role is confirmed** (or at minimum document
   the role at the declaration) so the next writer doesn't re-invent the
   wrong default.

General form: a reader reverse-engineered from a corpus captures the
corpus's *distribution* of a format, not the engine's *grammar*; the two
agree on every native file and disagree exactly where a writer has to make
something up. The disassembled parser is the only oracle for generated
output — a static test of it is cheap (minutes) next to a live crash
investigation (a day).
