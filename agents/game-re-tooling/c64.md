# Commodore 64 / 1541 targets

Worked example for everything here: WIME C64 (`middilgard`,
`docs/wime/c64/engine.md`, `tools/wime/c64/extract-nib.py`).

- **NIBTools raw-GCR images (`MNIB-1541-RAW`)**: 0x100-byte header of
  `(halftrack, density)` pairs, then 8,192 bytes of raw GCR bitstream per
  track. Decode by finding bit-level sync runs (≥ 8 one-bits) and reading
  5-bit GCR codes from the end of the run — the phase is not byte-aligned.
  **Trap:** a lenient GCR table (invalid codes mapped to nearest valid) plus
  a per-block phase search lets ~6% of garbage phases pass the sector XOR
  checksum by luck, silently corrupting chain links and directory entries.
  Once a fixed phase is established empirically (WIME: data blocks always
  decode 10 bits after the sync run), pin it. Trailing tracks (36–41)
  byte-identical to track 35 are a dump artifact of a drive that can't step
  past 35, not data.
- **Custom loader ≠ custom filesystem.** Fully custom GCR *sector headers*
  (scramble/interleave bytes where the stock header checksum lives — which
  alone is enough to make the KERNAL unable to read the disk) routinely sit
  over a bone-stock CBM BAM/directory/chain filesystem. Decode the two
  layers separately before writing "custom disk format".
- **Chain files: the final sector's second link byte is the last-used-byte
  offset, not a sector number** — the sector contributes `raw[2 : n+1]`
  bytes, not 254. Ignoring this pads every file to a 254-multiple; see
  lesson `extracted-file-sizes-all-multiples-of-block-payload.md`. PRG
  payloads then start with a 2-byte LE load address.
- **A multicolor bitmap picture is a three-part payload, not bitmap +
  external palette**: bitmap (8 bytes/cell) + screen RAM (pens 01/10, one
  byte/cell) + colour RAM (pen 11, one byte/cell) + the `$D021` background
  register. A self-contained picture blob carrying all three has an 8:1:1
  byte ratio (e.g. 4,000+500+500 for 20×25 cells) — that ratio is the tell.
  Colours render with the fixed VIC-II palette (Pepto values); there is no
  further palette to find. Cell order can differ per asset family in the
  same game (WIME: portraits row-major, scene backdrops column-major).
- **radare2 handles 6502 (`-a 6502 -m <loadaddr>`) but prints load addresses
  that read like file offsets and emits heavy ANSI colour** — two WIME
  sessions found a ~100-line hand-rolled 6502 disassembler taking the real
  load address faster to trust than fighting r2's output.
